**平台备案与域名备案必须分开处理**

云托管私有调用可以省去自有 API 域名配置与域名备案，但不免除小程序自身备案。腾讯云官方介绍中的“免备案”对应私有协议的域名访问方式；工信部备案规则明确包含小程序分发，并要求先备案后服务。[腾讯云私有调用说明](https://developer.cloud.tencent.com/article/1866155)、[工信部备案通知](https://ahca.miit.gov.cn/xxgkhlwgl/wzgl/art/2023/art_00c93cb439bd4943a0d8ab569561349b.html)、[小程序先备案后服务说明](https://gdca.miit.gov.cn/xwdt/gzdt/art/2024/art_9751673b67fc4d7a8878637f09eae7af.html)。

备案、平台要求的认证、类目审核、代码审核和正式发布是不同步骤。应在公众平台核对每项实际状态，不能从“已有 AppID”推断已经满足其余条件。管局对齐全准确材料的备案处理期限规定为二十个工作日内，这不是本项目必然需要二十天，也不是能在六天内完成的保证。[备案通知](https://ahca.miit.gov.cn/xxgkhlwgl/wzgl/art/2023/art_00c93cb439bd4943a0d8ab569561349b.html)。

**实施顺序和每阶段验收标准**

1. **立即推进平台手续，固定首发范围。** 管理员核对并推进备案、平台要求的认证和服务类目，确认报名和参赛人。首发以微信内普通办公文件转换和 OCR 为主，暂不增加支付、AI 聊天等新模块。核对 CONTEXT 的“AI 文档转换”与当前 UI 的“易换文档 AI”，以平台最终核准名称统一。通过标准是平台事项有真实状态和剩余步骤，产品范围可用于填写审核材料。
2. **完成一条真实云端主链路。** 先打通微信身份、单文件上传、一个普通转换、结果下载；再覆盖 OCR 和多文件。涉及 API/Worker 存储层、迁移、小程序 transport、CloudBase 入口。当前迁移头005应保留，云存储接续新的迁移。保持 Web/local 路径和现有权限、配额、OCR恢复语义。通过标准是真机能调用目标环境并在重启后找回记录及文件。
3. **补文件生命周期、隐私和资源保护。** 先统一 ADR0006 的“整条记录删除”与云设计的“文件过期保留元数据”差异，再实现目标行为；云端资源预算与现有游客策略也需明确作用范围。补隐私/服务说明、第三方披露、真实支持/删除请求渠道及普通文档限制提示。通过标准是披露内容与数据库、源文件、产物、日志的实际留存一致，清理可重试且不与活动任务竞争。
4. **修复并验收首发公开能力。** 回放表单、透明图、单文件合并和永久错误场景；未能保证正确性的输入必须修复或明确拒绝，不能静默丢数据。Android/iOS 分别覆盖聊天文件、相册/拍照、PDF/DOCX/图片/TXT 结果、保存转发、重新进入历史、权限拒绝、弱网、后台切换、过期登录和跨账户访问。首发保留的12类转换全部需要成功/失败边界验收，不能只演示一个顺利样例。
5. **冻结发布版本并完成赛事材料。** 固定代码快照与构建配置，补迁移/备份/回退说明和依赖处置记录；完成介绍PDF、正式二维码、授权书及报名资料。审核通过后正式发布，记录发布时间，再提交作品并保留回执。演示视频作为辅助材料，不伪造用户数、成功率或节省时间数据。
